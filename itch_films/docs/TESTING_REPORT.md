## 2. Тестирование системы изображений

### 2.1 Архитектура системы

`get_movie_image(film_id, genre=None)` — три шага выбора постера:

```
film_id → [1] IMAGE_OVERRIDES (5 записей, ручные исправления)
        → [2] FILM_IMAGES     (55 записей, visual keyword)
        → [3] GENRE_IMAGES[жанр][film_id % 20]  (формула)
        → DEFAULT_IMAGE        (если жанр неизвестен)
```

### 2.2 Исправление битого URL (HTTP 404)

В ходе HTTP-проверки всех URL обнаружен один битый адрес:

### 2.3 Поддержка film_id > 100

**Проблема:** `FILM_GENRE` содержит только film_id 1–100. Для фильмов с film_id > 100 функция `get_movie_image()` возвращала `DEFAULT_IMAGE` — одна и та же заглушка для всех.

**Причина:** в `routes.py` жанр фильма не передавался в `get_movie_image()`, хотя функция уже принимала параметр `genre=None`.

**Исправление** — одна строка в `routes.py`:
```python
# Было:
movie["image_url"] = get_movie_image(movie["film_id"])

# Стало:
movie["image_url"] = get_movie_image(movie["film_id"], movie.get("genre"))
```

**Проверка на реальных данных** (10 фильмов из MySQL с film_id > 100):

|---|---|---|---|
| 374 | Sci-Fi | DEFAULT_IMAGE | `Sci-Fi[374 % 20]` = `Sci-Fi[14]` |

### 2.6 Collision Resolver в результатах поиска

**Проблема:** формула `film_id % 20` циклически повторяется каждые 20 номеров. При поиске по жанру MySQL возвращает ~60 фильмов — значит, каждый URL-слот используется ~3 раза. Два фильма с `film_id % 20 == одно значение` получали одинаковое изображение в одной выдаче.

**Пример коллизии:**
```
film_id 27  % 20 = 7  → Sports[7]
film_id 447 % 20 = 7  → Sports[7]   ← одна и та же картинка
```

**Моделирование (2026-06-21):** симуляция для 4 жанров с реальными film_id 1–100 плюс 12 гипотетических film_id > 100:

| Жанр | film_id через формулу | БЕЗ resolver | С resolver |
|---|---|---|---|
| Animation | 15 | 7 коллизий | 0 коллизий |
| Comedy | 14 | 7 коллизий | 0 коллизий |
| Sports | 14 | 10 коллизий | 0 коллизий |
| Travel | 16 | 10 коллизий | 0 коллизий |

**Решение:** добавлен resolver в `routes.py` (~10 строк, только в функции `search()`). `movie_images.py` не изменён.

Алгоритм:
```
used_images = set()
для каждого фильма в результатах:
    url = get_movie_image(film_id, genre)
    если url НЕ в used_images → назначить, добавить в set
    если url УЖЕ в used_images → перебрать (base_idx + offset) % 20
                                  взять первый свободный слот
                                  если все 20 заняты → fallback на исходный url
```

**Границы гарантии:**
- Первые 20 фильмов одного жанра в выдаче — всегда уникальные изображения.
- С 21-го фильма того же жанра — fallback (повтор неизбежен: в GENRE_IMAGES всего 20 слотов).
- Фильмы из FILM_IMAGES и IMAGE_OVERRIDES resolver не затрагивает — их URL добавляются в `used_images` как есть.
